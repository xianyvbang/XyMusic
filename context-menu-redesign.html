右键菜单重设计 · Signal Panel

现有歌曲右键菜单把 8 个动作平铺在一张 220px 的卡片里：图标、文字、箭头层级完全一致，打开后也不知道操作的是哪首歌。新方案沿用设置页的 Signal Deck——顶部一条曲目轨道说明「在对谁操作」，中间用等宽分组标签和 1px 细线切成三段，悬停时左侧亮起 2px 主色导轨确认落点。播放页的歌词偏移菜单是另一种形态：它需要连续微调，因此单独设计成一台调校台（见 05）。

设计取向

先分组，再排优先级，最后补上下文

八项不该等权。旧菜单把「播放」和「定时关闭」放在同一条流水线上，中间没有任何停顿。新方案按使用频率切成 播放 / 信息 / 播放控制 三段，组间用 1px 细线隔开，高频动作永远落在鼠标刚打开的位置。

分组标签是等宽小字。沿用设置页的 9px / 字距 .18em / 大写 规格，左侧压一条 3px 主色短标。它足够安静，不会和条目标题抢注意力，但扫一眼就知道自己在哪一段。

补上「在对谁操作」。桌面端右键常常在长列表里发生，菜单顶部加一条 34px 曲目轨道：封面 + 歌名 + FLAC 44.1 kHz 元数据，底部用等宽读数条提示 Esc 与项数。两处都不占条目的宽度，菜单仍然保持在 248px。

状态与交互

四种条目状态、键盘约定与边界处理

条目四态

DISABLED = 40% 不透明度，不换色

交互约定

  • 悬停 120ms 打开子菜单，移出 200ms 后关闭，斜向移动到子菜单时不会误关。
  • 点击先执行回调、再 dismiss()，与现有 withDismissBehavior 顺序保持一致。
  • 定位菜单超出窗口右/下边缘时整体翻转并保留 8px 内边距，子菜单优先向左展开。
  • 键盘Esc 关闭整条链路，↑↓ 移动、→ 进入子菜单、Enter 执行。
  • 分组顺序固定播放 → 信息 → 播放控制，位置记忆比数量更重要，不随场景增减而重排。
  • 空状态没有歌单时「加入歌单」保留但禁用，右侧显示「无歌单」，避免条目突然消失导致误点。
05

播放页 · 歌词偏移菜单

与歌曲菜单同一套外壳，只把读数提亮
LYRICS SYNC

旧实现的问题不是样式，是形态。歌词偏移菜单当前是 5 条纯文字条目：第一条禁用充当「读数」，后四条是动作。用户得先读一行 偏移: 0s，再在下面找到「向前 / 向后」，调整后还要再点「确定」——三次视线跳转才能完成一次微调。

它应该和歌曲菜单长在一起。右键菜单是同一个组件在不同场景的投影，宽度、行高、分组、悬停反馈都该一致。所以这里不另起一套「调校台」外壳，而是直接复用上面的外壳：加强读数条 + 微调组 + 操作组。区别只有两处——读数条里的数值放大到 16px 主色，「确认偏移」用主色文字标出提交语义。

偏移没有上限。不设刻度尺也不设边界，连续点击时读数持续累加，视线始终停在同一个数字上。「重置」在 0 点自动禁用，避免无效操作。

它不应该自动关闭。这是唯一需要连续多次操作的菜单，任何一次点击后菜单消失都会打断调校。底部读数条明确写出「不自动关闭 / Esc 放弃预览」，并把取消语义从「关闭」改成「放弃预览」，与 onCloseRequest 里重置预览值的现有逻辑对齐。

02

04
