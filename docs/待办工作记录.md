**现状**：

- 下载目录目前由 `DownloadPlatformFiles.defaultDownloadDirectory` 解析后写入 `DownloaderConfig.finalDirectory`，用户无法修改。
- 设置页中的「歌曲缓存位置」只展示 `downloaderManager.config.finalDirectory`，点击仅复制路径，没有选择目录的入口。
- 已有可参考的实现：播放缓存目录（`cacheFilePath`）已支持通过系统目录选择器切换并持久化，下载目录可复用同样的交互与持久化方式。

**要点**：

- 在设置页「歌曲缓存位置」处增加「修改下载目录」入口，点击后调用平台目录选择器（Android 使用 SAF 目录授权，JVM 使用 FileKit 目录选择器）选择目标目录。
- 将选择的目录持久化到设置表（新增字段，保持默认值为空表示使用平台默认目录），下载管理器初始化时用该值覆盖 `DownloaderConfig.finalDirectory`，重启后生效。
- 提供「恢复默认目录」操作，清空自定义路径后回落到平台默认下载目录。
- 切换目录时给出明确策略：已下载文件不做自动搬运（保持原路径可播放），或提供迁移选项并在迁移时校验 MD5；需保证下载任务记录中的 `filePath` 与实际文件位置一致，避免播放/清理时找不到文件。
- 目录不可用（无写权限、磁盘空间不足、路径被删除）时给出提示并回退到默认目录，不阻塞下载功能。
- 校验：设置中修改下载目录 → 新建下载任务的文件落在新目录 → 重启应用后仍指向新目录 → 恢复默认后回到平台默认下载目录；无权限目录被拒绝并提示。

- 现有调用方：composeApp 内 9 处 import（`JvmDownloadScreen`、`JvmStorageSettingsSection`、`JvmMemoryManagementScreen`、`DownloadScreen`、`MemoryManagementViewModel`、`CacheLimitViewModel`、`MusicCacheSizeInfo` 等），下载模块 1 处内部调用。

**要点**：

- 下沉目标模块选 `:xy-platform`（commonMain）：它已被 `download` 与 `composeApp` 同时依赖，且当前只放跨平台基础设施，适合承接无 UI 依赖的纯 Kotlin 工具。

- `parseStorageBytes()`、`formatStorageLabel()` 一并迁移，避免只搬一半导致两处并存。
- 删除 `DownloadStorageGuard` 内的私有 `formatBytes`，改为调用共享实现。

## 10. JVM 端数据目录改为平台标准用户目录

**目标**：把 JVM 端数据根目录从「安装盘盘符根目录 + `XyMusicData`」改为各平台约定的用户数据目录，避免落到只读位置，也避免与安装路径绑定。

**现状**：

- [ContextWrapper.jvm.kt](file:///D:/androidPro/XyMusic/xy-platform/src/jvmMain/kotlin/cn/xybbz/platform/ContextWrapper.jvm.kt#L62-L69) 的 `resolveDataDirectory()` 当前取 `installationDirectory.toPath().root`（即安装盘盘符根目录）再拼 `${appName}Data`，在本机表现为 `D:\XyMusicData`。
- 数据库、缓存、临时、下载目录都从 `dataDirectory` 派生：`database`、`cache`、`temp`、`Downloads/XyMusic`。
- 盘符根目录（尤其是 `C:\`）普通用户通常无写权限，MSI 安装到 `C:\Program Files\` 后该方案会直接建库失败。
- 已有覆盖入口：系统属性 `cn.xybbz.dataRoot`（`DATA_ROOT_PROPERTY`），可指定任意数据根目录。
- 相关测试：[ContextWrapperJvmTest.kt](file:///D:/androidPro/XyMusic/xy-platform/src/jvmTest/kotlin/cn/xybbz/platform/ContextWrapperJvmTest.kt#L16-L37) 断言了默认路径为盘符根目录，改动后需同步更新。

**通用做法（各平台约定）**：

| 平台 | 配置/数据 | 缓存 | 用户可见文件 |
| --- | --- | --- | --- |
| Windows | `%APPDATA%\XyMusic`（Roaming）或 `%LOCALAPPDATA%\XyMusic` | `%LOCALAPPDATA%\XyMusic\Cache` | `%USERPROFILE%\Music\XyMusic` |
| macOS | `~/Library/Application Support/XyMusic` | `~/Library/Caches/XyMusic` | `~/Music/XyMusic` |
| Linux | `~/.local/share/XyMusic` | `~/.cache/XyMusic` | `~/Music/XyMusic` |

- Roaming 会随域账户漫游同步，只适合小而重要的配置；数据库、缓存等大体积数据必须放 Local，否则会拖慢登录同步。
- 主流桌面应用参考：Electron 默认 `%APPDATA%\<产品名>`；Chrome、VS Code 把大体积数据放 `%LOCALAPPDATA%`；JetBrains IDE 配置放 Roaming、缓存放 Local。

**建议的目录映射**：

| 现有目录 | 建议改为 |
| --- | --- |
| `dataDirectory/database` | `%LOCALAPPDATA%\XyMusic\database` |
| `dataDirectory/cache` | `%LOCALAPPDATA%\XyMusic\cache` |
| `dataDirectory/temp` | `%LOCALAPPDATA%\XyMusic\temp` |
| `dataDirectory/Downloads/XyMusic` | `%USERPROFILE%\Music\XyMusic`（或保留 `Downloads\XyMusic`） |

**要点**：

- 修改 `resolveDataDirectory()`：优先级为「`cn.xybbz.dataRoot` 覆盖属性 > 平台标准用户数据目录」。
  - Windows 取 `System.getenv("LOCALAPPDATA")`；macOS/Linux 取 `System.getenv("XDG_DATA_HOME")`，为空时回退 `~/Library/Application Support` 或 `~/.local/share`。
  - 最终目录为 `<用户数据目录>/<appName>`，与现有 `appName` 解析保持一致。
- 保留 `cn.xybbz.dataRoot` 覆盖能力，绿色版/便携版可用它把数据固定到安装目录旁（`-Dcn.xybbz.dataRoot=<安装目录>`），无需改代码。
- 不采用「默认放安装目录」方案：jpackage MSI 默认装到 `C:\Program Files\XyMusic\`，普通用户启动时无写权限，数据库、缓存、临时文件都会失败；如需兼顾绿色版，可加「安装目录可写则用之，否则回退用户目录」的探测逻辑。
- 老数据迁移：数据库路径变化后，`D:\XyMusicData` 中的歌单、播放记录、下载记录会被视为新安装。需要加一次性迁移逻辑，把旧目录下的 `database`、`cache`、`temp` 搬到新目录；迁移完成打标记，避免重复执行；迁移失败时保留旧目录并给出提示，不阻塞启动。
- 同步更新 `ContextWrapperJvmTest` 的默认路径断言，并补一条「`cn.xybbz.dataRoot` 覆盖时所有子目录从覆盖目录派生」的用例（已有 `dataRootPropertyOverridesRuntimeDriveRoot` 可复用）。
- 校验：全新安装后数据落在用户数据目录；`cn.xybbz.dataRoot` 覆盖生效；老版本升级后歌单/播放记录/下载记录仍在；`C:\Program Files` 安装场景下建库成功。
